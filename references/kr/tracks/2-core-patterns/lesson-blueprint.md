# 핵심 문법 패턴 — 한 과의 페이지 구성

**이 문서는 목차가 아니라 지도다.** 어떤 페이지가 어떤 순서로 오는지, 각 페이지가 무엇을
하는 자리인지만 적는다. 실제 마크업과 말투는 여기서 베끼지 말고 **원본 덱**에서 가져온다.

- **원본 덱 (source of truth):** [`../../trial/lessons/trial-2-patterns-short.html`](../../trial/lessons/trial-2-patterns-short.html)
- **원본에서 판매 페이지를 뺀 것:** [`sample-lesson.html`](./sample-lesson.html) — 새 과는 이 모양으로 나온다
- **이 과에 무엇을 담을지:** [`toc/lesson-NNN.md`](./toc/index.md)
- **컴포넌트 마크업:** [`../../AUTHORING.md`](../../AUTHORING.md)

이 지도를 먼저 읽고 페이지 계획을 세운 다음, **원본 덱을 통째로 읽는다.** 원본을 건너뛰지
말 것 — 페이지 구조는 이 문서로 옮겨지지만 튜터 말투, 오답 고르는 감각, 예문의 리듬은
옮겨지지 않는다. 그것들이 과의 품질을 결정한다.

---

## 전체 골격

한 과 = **도입 2장 + 패턴 파트 2개 + 통합 파트 1개 + 마무리 2장.** 28장 안팎.

| # | data-page-id | 자리 |
| ---: | --- | --- |
| 1 | `lesson-goal` | 오늘 끝나면 할 수 있는 대화를 통째로 보여준다 |
| 2 | `words-you-know` | 이미 아는 것에서 출발한다는 동기 부여 |
| 3–13 | `part1-*` | 패턴 A — 아래 「패턴 파트」 사다리 |
| 14–24 | `part2-*` | 패턴 B — 같은 사다리 |
| 25–28 | `part3-*` | 두 패턴을 한 장면에서 합친다 |
| 29 | `korea-trip` | 보너스 장면 — 실제 상황에 그대로 얹기 |
| 30 | `native-tip` | 원어민이 실제로 줄여 말하는 방식 |

**판매 페이지는 트랙 과에 없다.** 원본 덱에는 앞에 `cover` · `greeting` · `trial-intro`,
뒤에 `todays-result` · `closing` 이 붙어 있다. 이 다섯 장은 체험 수업 전용이므로 새 과를
만들 때는 넣지 않는다. 대신 살아남는 첫 페이지(`lesson-goal`)가 `data-act` 를 직접 들고
있어야 한다 — 원래 `cover` 의 `.brand-title` 에서 오던 값이다.

## 패턴 파트 (part1 · part2 가 똑같이 쓰는 사다리)

**받아들이기 → 알아보기 → 만들기.** 이 순서가 이 트랙의 교육 설계 전부다. 페이지를 빼도
되지만 **순서를 바꾸거나 건너뛰면 안 된다** — 뒤 페이지는 앞 페이지가 이미 입에 붙었다고
가정하고 모범 문장을 치운다.

| data-page-id | 컴포넌트 | 하는 일 | 모범 문장 |
| --- | --- | --- | :---: |
| `partN-intro` | `.transition-page` | 패턴 이름과 한 줄 설명 | — |
| `pN-teach` | `.pattern-meaning` + `.sent-hero` + `.sent-more` | **뜻과 쓰임** 먼저, 그다음 문장 통째로. 튜터가 읽는다 | 있음 |
| `pN-read` | `.model-line` ×4 | 학습자가 혼자 읽는다. 모범은 아직 화면에 | 있음 |
| `pN-*-rule` | 도식 (`.batchim` 등) | 형태 규칙 한 개. **문법 설명은 여기 한 장뿐** | — |
| `pN-choose` | `.choose-row` + `.opt` | 둘 중 고르기 — 알아보기의 마지막 단계 | 있음 |
| `pN-reorder` | `.task-block` ×4 + `.answer-box small` | 칩을 순서대로. 한 문장당 **의미 덩어리 4개**(천장이자 기본값, 3개는 정말 짧은 문장만) | 없음 |
| `pN-fill` | `.task-block` + `.answer-box` | 빈칸 — 패턴 자리만 비운다 | 없음 |
| `pN-translate` | `.task-block` + `.answer-box` | 일본어를 보고 한국어로. 힌트는 어휘만 | 없음 |
| `pN-write` | `.task-block` + `.answer-box tall` | 자기 이야기. 정답이 없는 첫 페이지 | 없음 |

`pN-question-teach` / `pN-question-read` 처럼 한 파트가 형태를 하나 더 얹으면 `teach`+`read`
짝을 그 자리에 한 번 더 넣는다. 사다리 자체는 그대로다.

**`pN-teach` 는 뜻과 쓰임으로 연다.** 파란 상자에 `.pattern-meaning` 을 얹고 맨 앞에
`뜻과 쓰임 <small>意味・使い方</small>` 키커를 둔다. 첫 문장은 이 형태가 일본어로 무엇인지
(`‘~してみてください’예요.`), 둘째 문장은 **언제 손이 가는지**(`한번 해 보라고 권할 때 써요.`)다.
그다음에 이 과의 원래 대본이 이어진다. 만드는 법은 여기 쓰지 않는다 — 그건 `pN-*-rule` 의 일이다.

이 상자가 없으면 「언제 쓰나」가 갈 곳이 없어서 규칙 페이지로 흘러든다. 규칙 페이지는 형태만
그릴 수 있으므로, 쓰임을 거기 넣으면 학습자가 실행할 수 없는 도식이 된다 — 과 46 이 께서/께서는
을 그렇게 그렸다가 다시 뜯었다. 컨텍스추얼 트랙이 먼저 쓰던 방식이고, 이제 두 트랙이 같다.

**빈칸에 무엇을 비우는가는 규칙이 있다.** 힌트가 없는 빈칸은 그 과의 패턴(조사 · ~요 어미)만
비운다. 나머지 일본어 단어는 전부 미리 준다. `AUTHORING.md` § 빈칸 채우기를 볼 것.

**칩을 어디서 자르는가에도 규칙이 있다.** 한 문장은 의미 덩어리 4개가 기본이자 천장이다.
문장이 정말 3덩어리뿐이면(저는 · 학생 · 이에요) 3개로 둔다 — 필요 없는 시간·장소를 넣어
4개를 만들지 않는다. 대신 **하나인 것을 쪼개서 4개를 만들지도 않는다**: 합성 명사(`일본 사람`),
조사와 그 명사, 어미와 그 어간은 한 칩이다. 반대로 **이미 문장 안에 있는 네 번째 덩어리를
옆에 붙여 두지도 않는다** — 같은 페이지에서 `학생` + `이에요?` 로 자르고 다음 줄만
`한국 사람이에요?` 로 붙이면, 짧은 문장이 아니라 같은 문법을 두 가지로 자른 것이다.
문장을 보고 경계를 정한 다음, 그 페이지 안에서는 같은 기준을 지킨다.

## 통합 파트 (part3)

두 패턴이 **한 장면에서 서로를 부르는** 자리다. 패턴 B가 필요한 이유가 패턴 A를 썼기
때문이어야 한다 — 질문과 대답, 부탁과 응답처럼.

| data-page-id | 컴포넌트 | 하는 일 |
| --- | --- | --- |
| `part3-intro` | `.transition-page` | 장면을 연다 |
| `p3-model` | `.dialogue` | 완성된 대화. 튜터가 한쪽, 학습자가 다른 쪽 |
| `p3-complete` | `.dialogue` + `.answer-box` | 같은 대화, 학습자 대사가 비어 있다 |
| `p3-freetalk` | `.dialogue` + `.answer-box small` | 진짜 자기 이야기로 같은 장면 |

`korea-trip` 은 같은 패턴을 **다른 장면**에 얹어 전이를 확인한다(게스트하우스, 식당…).
`native-tip` 은 원어민이 실제로 줄여 말하는 방식 한 개 — 새 문법이 아니라 관찰이다.

**빈칸 하나에는 질문 하나다.** `p3-complete` · `p3-freetalk` · `korea-trip` 에서 상대 대사가
답을 하나 받는다면 묻는 것도 하나다. 두 개는 뒤엣것이 앞엣것을 **좁힐 때만** 쓴다 —
「추워요? 더워요?」 같은 양자택일, 또는 본 질문을 여는 예/아니오. 세 개는 안 되고,
서로 다른 질문을 `그리고` 로 잇는 것도 안 된다. 답이 세 개 필요한 장면이면 턴을 세 번
준다 — 짧은 질문, 빈칸, 다음 질문. 턴은 싸고 초급 학습자의 작업기억은 비싸다.

## 브리프를 읽을 때 헷갈리는 두 가지

**「아직 아님」은 학습자가 만들어 말할 것에만 걸린다.** 튜터가 소리 내어 읽는
`.section-subtitle` 은 자연스러운 한국어여야 하고, 거기에는 그 과가 아직 안 가르친 형태가
얼마든지 나온다 — 체험 덱도 1과에서 `-거든요` · `-ㄹ게요` 를 튜터 입으로 쓴다. 제약을
튜터 말투에까지 밀어붙이면 한국어가 어색해지고, 그게 더 나쁘다.

**`.batchim` 은 받침 규칙 전용이 아니다.** 규칙이 소리로 갈리지 않을 때(에 vs 에서처럼
뒤에 오는 동사가 정하는 경우)는 `.bt-eq` 안에 글자 타일과 화살표를 빼고 `.bt-out` 만
남긴다. 상자는 그대로 서고, `.bt-head` 가 「무엇을 보고 고르는가」를 맡는다. 소리로
갈리지 않는 규칙에 글자 타일을 억지로 넣으면 학습자가 없는 규칙을 찾는다.

## 이 트랙에서 하지 않는 것

- **문법 이름을 먼저 가르치지 않는다.** 학습자는 장면에서 문장을 통째로 빌려 슬롯만 바꾼다.
  `pN-*-rule` 한 장이 형태 설명의 전부이고, 그마저 「이해」 목표지 「발화」 목표가 아니다.
- **아직 안 배운 것을 예문에 쓰지 않는다.** 브리프의 「아직 아님」이 그 목록이다.
- **모범 문장을 사다리 아래쪽까지 남기지 않는다.** `reorder` 부터는 화면에서 치운다.
- **한 장에 활동 두 개를 넣지 않는다.** 페이지 하나 = 활동 하나. `ux-philosophy.md` 참조.
